# Модели и сервисы: задание 5.2

Сценарии сопоставлены с контрактом [specification.yml](specification.yml).
Из задания 5.1 используются MongoDB-клиент, DI-контейнер и модели User/Offer.

| Сценарий | Модель и сервис | Методы и DTO |
| --- | --- | --- |
| Регистрация и поиск пользователя при входе | UserEntity / UserModel / UserService (существовали) | create(CreateUserDto, salt), findById, findByEmail |
| Загрузка аватара | UserService | updateById(UpdateUserDto) |
| Создание и изменение предложения | OfferEntity / OfferModel / OfferService (существовали) | create(CreateOfferDto), updateById(UpdateOfferDto) |
| Список и подробности предложений | OfferService | find(limit = 60), findById; необязательный userId для избранного |
| Премиальные предложения города | OfferService | findPremiumByCity: до 3 предложений |
| Удаление предложения | OfferService | deleteById: также удаляет комментарии и ссылки в избранном |
| Добавление и получение комментариев | Новые CommentEntity / CommentModel / CommentService | create(CreateCommentDto), findByOfferId: последние 50 |
| Избранное | UserEntity.favoriteOffers и OfferService | setFavorite(SetFavoriteDto), findFavorites |

Списки сортируются по postDate по убыванию, при совпадении дат — по _id.
Комментарии ссылаются на автора и предложение через ObjectId; дата комментария
и createdAt/updatedAt заполняются автоматически. Город и координаты остаются
вложенными значениями: отдельные коллекции им не нужны.

При создании предложения rating и commentsCount равны 0, даже при импорте TSV.
DTO исключают вычисляемые поля; UpdateOfferDto также исключает автора.
Каждый сохранённый комментарий вызывает addRating: одна атомарная операция
увеличивает commentsCount и служебную сумму ratingTotal, затем рассчитывает
rating как среднее, округлённое до десятых. Сумма не округляется и исключена
из обычных запросов. Это предотвращает потерю параллельных оценок и накопление
ошибки от использования уже округлённого среднего.

Сохранение комментария и обновление предложения — две операции. Ошибка базы
между ними может потребовать восстановления статистики; транзакции не добавлены,
чтобы сохранить совместимость с локальной standalone MongoDB из задания 5.1.

Избранное хранится отдельно для каждого пользователя: $addToSet исключает
дубликаты, $pull обеспечивает повторяемое удаление. isFavorite рассчитывается
при чтении, для анонимного пользователя равен false и в OfferModel не хранится.

Валидация новых моделей, HTTP-контроллеры, проверка прав автора, JWT и выдача
публичных DTO без пароля относятся к следующим заданиям. Сервисы возвращают
ссылки на авторов; перед формированием HTTP-ответов их нужно раскрывать с выбором
публичных полей. Поиск по email и хеширование пароля из задания 5.1 сохранены.

Проверка: `npm run lint`; `npm test`. Для интеграционных проверок в PowerShell:
`$env:TEST_MONGO_URI = 'mongodb://127.0.0.1:27017'; npm test`.
Тесты используют уникальные временные базы и удаляют только созданные ими данные.
