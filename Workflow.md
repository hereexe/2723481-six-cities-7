# Как работать над проектом

## Окружение

Для удобства работы над проектом используются инструменты из **Node.js** и **npm**. Все необходимые настройки произведены. Убедитесь, что на рабочем компьютере установлен актуальный LTS релиз Node.js**. Актуальная версия **Node.js** указана в файле `package.json` в поле `node`. Затем, в терминале, перейдите в директорию с проектом и _единожды_ запустите команду:

```bash
npm install
```

Команда запустит процесс установки зависимостей проекта из **npm**.

### Сценарии

В `package.json` предопределено несколько сценариев.

#### Скомпилировать проект

```bash
npm run compile
```

Создаст директорию `dist` и скомпилирует проект.

#### Удалить скомпилированный проект

```bash
npm run clean
```

Удаляет директорию `dist`. Используется перед компиляцией.

#### Собрать проект

```bash
npm run build
```

Выполняет сборку проекта: удаляет ранее скомпилированный проект и компилирует заново.

#### Проверить инфраструктуру приложения

```bash
npm test
```

Собирает проект и проверяет запуск через DI-контейнер, загрузку `.env`, обязательность и валидацию настроек, аргументы импорта и формирование URI. В проверках конфигурации подключение к MongoDB заменено заглушкой.

Чтобы также проверить реальное сохранение и поиск документов, укажите URI работающей MongoDB (PowerShell):

```powershell
$env:TEST_MONGO_URI = 'mongodb://127.0.0.1:27017'
npm test
```

Интеграционный тест создаёт уникальную временную базу, проверяет импорт, ссылки на автора, хеширование паролей, временные поля и завершение CLI при ошибках. После проверки временная база удаляется. Без `TEST_MONGO_URI` этот тест пропускается.

#### Проверить линтером

```bash
npm run lint
```

Запуск проверки проекта статическим анализатором кода **ESLint**.

Линтер проверяет файлы только внутри директории `src`.

**Обратите внимание**, при запуске данной команды, ошибки выводятся в терминал.

#### Запустить ts-модуль без компиляции

```bash
npm run ts -- <Путь к модулю с ts-кодом>
```

Пакет `ts-node` позволяет выполнить TS-код в Node.js без предварительной компиляции. Используется только на этапе разработки.

#### Запустить проект

```bash
npm start
```

В процессе запуска проекта будет выполнен процесс «Сборки проекта» и запуска результирующего кода.

Перед первым запуском скопируйте `.env-example` в `.env` в корне проекта и задайте свои значения:

| Переменная | Значение |
| --- | --- |
| `PORT` | Номер порта REST API сервера |
| `DB_HOST` | IP-адрес сервера базы данных (IPv4 или IPv6) |
| `DB_PORT` | Порт MongoDB, по умолчанию `27017` |
| `DB_NAME` | Название базы данных, по умолчанию `six-cities` |
| `DB_USER` | Пользователь MongoDB; оставьте пустым для локальной базы без авторизации |
| `DB_PASSWORD` | Пароль MongoDB; при заполненном `DB_USER` используется `authSource=admin` |
| `SALT` | Непустая строка со случайным набором символов для хеширования паролей |

Переменные `PORT`, `DB_HOST` и `SALT` обязательны. `.env` исключён из Git. Уже установленные переменные окружения имеют приоритет над файлом. При неверных настройках приложение пишет ошибку через логер и завершается с кодом `1`.

Приложение устанавливает соединение с MongoDB и выводит номер порта; HTTP-сервер будет добавлен в следующих заданиях. Попытка подключения, успешное соединение и ошибки отражаются в JSON-логах. URI и пароль подключения в логи не выводятся. Для форматирования логов через `pino-pretty` используйте:

```bash
npm run start:dev
```

#### Запустить CLI

```bash
npm run cli -- --help
```

Собирает проект и запускает приложение с интерфейсом командной строки.

#### Запустить тестовый JSON-сервер

```bash
npm run mock:server
```

Запускает тестовый REST API сервер **json-server** на порту `3123` с данными из файла `mocks/mock-server-data.json`. Заготовки предложений доступны по адресу `http://localhost:3123/offers`. Сервер нужен для работы команды `--generate`.

Например, после запуска сервера можно сгенерировать тестовый TSV-файл и импортировать его:

```bash
npm run cli -- --generate 100 ./mocks/generated/offers.tsv http://localhost:3123/offers
npm run cli -- --import ./mocks/generated/offers.tsv "mongodb://127.0.0.1:27017/six-cities" "your-random-salt"
```

Команда `--import <path> <uri> <salt>` принимает полный URI MongoDB и соль для хеширования паролей. Используйте ту же соль, что указана в `SALT` приложения. При необходимости авторизации URI имеет вид `mongodb://user:password@127.0.0.1:27017/six-cities?authSource=admin`; специальные символы логина и пароля нужно закодировать через percent-encoding.

Импорт читает TSV построчно, создаёт пользователя или находит существующего по email и сохраняет предложение со ссылкой на автора. Пароль хранится в виде хеша scrypt. Соединение закрывается и при успешном завершении, и при ошибке. Уже сохранённые строки остаются в базе при ошибке последующих строк; повторный импорт добавляет предложения заново, используя существующих пользователей.

Директория `mocks/generated` исключена из Git — сгенерированные файлы не коммитятся.

### MongoDB и просмотр данных

Перед запуском приложения и импорта запустите MongoDB. Для просмотра базы установите [MongoDB Compass](https://www.mongodb.com/products/tools/compass). В Windows его можно установить командой:

```powershell
winget install --id MongoDB.Compass.Full --exact
```

В Compass создайте подключение с URI `mongodb://127.0.0.1:27017`, затем откройте базу `six-cities`. После импорта в ней будут отдельные коллекции `users` и `offers`. У обоих типов документов автоматически заполняются `createdAt` и `updatedAt`. Поле `offers.author` содержит ObjectId пользователя из `users`, а город и координаты хранятся внутри предложения как составные значения. Модель комментариев будет добавлена в следующем задании.

## Структура проекта

### Директория `src`

Исходный код проекта организован по следующим правилам:

- `application/` — класс приложения, который координирует работу компонентов.
- `shared/libs/` — общие инфраструктурные компоненты: `logger/`, `config/`, `database-client/`.
- `shared/modules/` — модули `user/` и `offer/`: схемы Mongoose, интерфейсы и реализации сервисов создания и поиска документов. Сервис пользователей поддерживает поиск по ObjectId и email, сервис предложений — по ObjectId.
- `shared/types/` — общие инфраструктурные типы и идентификаторы DI-компонентов.
- `types/` — типы предметной области, `helpers/` — функции для работы с предложениями и TSV.
- `container.ts` — привязки интерфейсов к реализациям в Inversify. Все сервисы создаются контейнером как singleton и передаются приложению через конструктор с `@inject`.
- `main.ts` — точка входа приложения; `cli.ts` — независимая точка входа утилиты для терминала, которой не нужен `.env`.

Имена директорий и файлов записываются в `kebab-case`, интерфейсы имеют суффикс `.interface.ts`, типы — `.type.ts`, перечисления — `.enum.ts`.
